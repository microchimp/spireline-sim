## Expected behaviour (game)
`FairyInABottle` is an automatic potion: its `ShouldDie` answers false for its owner and `AfterPreventingDeath` runs its `OnUse`, which heals 30% of max HP (at least 1) and consumes the potion. It is a creature-level death hook, so it applies to any lethal damage, including an event `CreatureCmd.Damage` (the Jungle Maze Adventure solo quest). Order inside the option: damage -> death prevented -> heal -> the option remaining effects (its gold gain). The run only ends if no prevention applies.

## Emulator mechanism and its other uses
- In combat the mechanism exists: `Core/CombatEngine.cs`, `PlayerIsDead` (spends the potion slot, sets HP to max(floor(30% of max HP), 1), then `RelicEffects.ApplyAfterPlayerHpChanged`; a static audit test (`Audit/StaticAuditPotionTests.cs`) says Fairy is spent before Lizard Tail).
- The run layer has no equivalent. Non-combat HP loss goes through `Core/Run/RunNonCombatEffects.cs::LoseHp` (applies Tungsten Rod, then clamps HP at 0); the Jungle Maze Adventure handler in `RunEngine.cs` calls `LoseHp` and then `GainGold`; the step-end check in `RunEngine.cs` (about line 1209) ends the run when `PlayerHp <= 0`. Other writers that can reach 0 in the run layer (find with `grep -n "PlayerHp = 0\|PlayerHp = Math.Max(0" src/Sts2Emulator/Core/Run/*.cs`): `RunNonCombatEffects.cs` about line 2622, `RunEngine.cs` about lines 82 and 5109. The post-combat copy in `RunEngine.cs` about line 2217 (`PlayerHp = Math.Max(0, ActiveCombat.PlayerHp)`) must keep working: a Fairy used inside the fight has already left the combat potion slots and must also leave the run slots.
- Other events with a possibly lethal HP cost use the same `LoseHp` (for example The Legends Were True, slowly-find-an-exit option, whose code comment says lethal is allowed and Step ends the run at 0). The fix covers all of them; the game revives in each.

## Fix sketch
Add in `RunNonCombatEffects` one helper `TryPreventDeath(RunState)`: if `PlayerHp <= 0` and the belt (`PotionSlots`) holds the Fairy potion id (look it up by name as `CombatEngine` does), clear that slot and set `PlayerHp = max((int)(PlayerMaxHp * 0.3m), 1)`; run the after-HP-changed relic hook the combat version runs only if one exists for the run state. Call it from `LoseHp` right after the clamp (matches the game: revive before the option later effects) and from every other writer found by the grep above that can end a run; keep the step-end check in `RunEngine` as the last guard. Keep Lizard Tail out unless the run layer already models it (then give it the combat order, Fairy first) and say so in the commit.
