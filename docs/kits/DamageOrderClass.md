## Symptom
B10 (the Pen Nib fix) found that four more card-level additive terms are added at the call sites AFTER `DmgFrom` has applied the card multipliers, so under a multiplier they are not multiplied while the game multiplies them: Accuracy's bonus for Shivs, Claw's accumulated `ClawDamage`, the `card.BonusDamage` adds (`CardEffects.cs` around lines 689, 705, 7671, 8343, 8479, 8642 at `4acd1698`), and Calcify's `OstyAttackDamage` where it wraps `Dmg(...)` (around 7323, 8021, 8072), while at 7828/7853/7877 `OstyAttackDamage` sits inside `DmgFrom` and is multiplied. No lockstep record is attached to this kit yet; the defect is read from the code and from the game's order (below). It is rare in play (a tenth Attack that is a Shiv or a Claw, a Gigantified Claw, a Minion card with bonus damage), which is why it never ranked, and it is cheap because B10 already built the shared site.

## Expected behaviour (game)
`Hook.ModifyDamage` for a card source runs, in this order: the enchantment's additive then multiplicative steps; every `ModifyDamageAdditive` listener (the card's own terms such as `AccuracyPower` for Shivs, Claw's counter, the card model's bonus damage, `CalcifyPower`; then the creature's `StrengthPower`, `VigorPower`; relic additive terms); then every `ModifyDamageMultiplicative` listener (`PenNib`, `VitruvianMinion`, `GigantificationPower`, `WeakPower`, `VulnerablePower`, ...); then the caps. So a Shiv (base 4) at Accuracy 4 on a Pen Nib tenth Attack deals (4 + 4) x 2 = 16, not 4 x 2 + 4 = 12; a Claw at `ClawDamage` 6 Gigantified deals (3 + 6) x 3 = 27, not 3 x 3 + 6 = 15.

## Emulator mechanism and its other uses
- The shared site is `CardEffects.DmgFrom` -> `ModifiedCardDamage(state, baseDamage, def, card, creatureAdditive)`, which since B10 returns `(damage + creatureAdditive) x factor - creatureAdditive` and lets `BuffSystem.IncomingDamage` add the creature terms back. The card-level additive terms belong INSIDE the base the multiplier sees: the root-cause fix is one parameter or one fold (a `cardAdditive`, or the call sites passing `base + term` into `DmgFrom` instead of `DmgFrom(base) + term`), applied at every call site listed above, not four separate patches. Keep `Thrash`'s `EatenAttackDamage` (no creature additive) and the switch-on early return exactly as they are.
- Other uses: every call site that computes a card's damage through `DmgFrom` and then adds something is in scope; grep `DmgFrom(` and `ModifiedCardDamage(` and list each site with what it adds after the call, so the kit's reviewer can check none is missed (the eight-case `PenNibStrengthTests` is the model for the new class).
